# ADR-0001: Native Kotlin engine; no adapter over the jsii Java library

- Status: Proposed
- Date: 2026-11-14

## Context

The brief asks whether `org.kollavarsham.converter:kollavarsham-converter` can serve as an isolated calculation adapter. Sprint 0 found:

- The artifact is generated by jsii from TypeScript. Its `jsii-runtime` dependency executes the JavaScript in a **Node.js child process**, which is unavailable on Android.
- The upstream engine uses a midnight month-start rule and Surya Siddhanta mean motions. It matches 11 of 14 observed Kerala month starts and agrees with a modern Kerala-rule computation for only 386 of 492 month starts (1990–2030).
- Kollavarsham → Gregorian conversion is not implemented upstream.
- No native Kotlin implementation exists.

## Decision

Implement the calendar engine natively in Kotlin from primary sources:

- Meeus for solar position and sunrise.
- Sewell & Dikshit for the Kerala rule.
- The Lahiri definition for the ayanamsa.

Peer implementations (Dart `kollavarsham`, AjeshAB, kollavarsham-js) are used **only as cross-checks**. No third-party code is copied.

## Consequences

- No runtime dependencies other than the Kotlin stdlib. The engine works offline and on Android.
- Higher initial effort, estimated at Sprint 2 plus part of Sprint 1.
- Validation stays independent of the peers, so their agreement is meaningful evidence.
- We own the astronomy code and must test it against T2 references (see VALIDATION_STRATEGY).
