# Kollavarsham Kotlin SDK 0.1.0-alpha01

The first preview of a Kotlin SDK for the Malayalam (Kollavarsham) calendar. It works offline, is thread-safe, and has no dependencies other than the Kotlin standard library in its core modules.

> **Preview release.** The API may change before 1.0 (ADR-0007). The calendar is carefully validated, but
> the cited almanac evidence is still being expanded (see "Accuracy" below).

## Artifacts

All under group `io.github.anjalymsajeev`:

| Artifact | What it gives you | Runtime dependencies |
|---|---|---|
| `kollavarsham-core` | Gregorian ↔ Kollavarsham conversion, validation, month boundaries, date arithmetic | kotlin-stdlib (+ astronomy) |
| `kollavarsham-astronomy` | Sun (VSOP87), Moon (ELP-2000/82), ΔT, Lahiri ayanamsa, sankranti, sunrise/sunset (opt-in API) | kotlin-stdlib |
| `kollavarsham-locale` | Malayalam and English names, ISO 15919 transliteration, Malayalam numerals, date formatting | kotlin-stdlib |
| `kollavarsham-panchangam` | Nakshatra, tithi, paksha, sunrise/sunset for any location; daily panchangam | kotlin-stdlib |
| `kollavarsham-festivals` | 25 Kerala festivals as rules; custom rules; dated observance lists (CSV) | kotlin-stdlib |
| `kollavarsham-android` | Compose month calendar (`KollavarshamMonthView`), `MonthGrid` (AAR, minSdk 21) | Compose UI, Foundation, Material3 |

Requirements:
- JVM 11+.
- Android minSdk 26, or lower with core library desugaring (for `java.time`).

## Highlights

```kotlin
val calendar = KollavarshamCalendar.create()
calendar.fromGregorian(LocalDate.of(2026, 11, 14))                              // 1202 Thulam 28
    .format(CalendarLocale.MALAYALAM, DateStyle.FULL, calendar)                 // "കൊല്ലവർഷം 1202 തുലാം 28, ശനി"
Panchangam.create().day(LocalDate.of(2025, 9, 5)).nakshatraAtSunrise           // Thiruvonam
FestivalCalendar.create().dateOf(KeralaFestivals.ONAM, 1202)                   // 2026-08-26
```

## Accuracy

- **Month starts** follow Kerala's rule (the sankranti before 3/5 of daytime at Thiruvananthapuram).
  - Sankranti times agree with a JPL-based ephemeris to about 1 s (1900–2025).
  - All 21 cited month starts are reproduced.
  - 30 months between 1900 and 2100 are borderline (the sankranti is within 10 minutes of the cut-off); `MonthBoundary.cutoffMargin` flags them.
- **Panchangam:** nakshatra boundaries agree with an independent reference to about 5 s, and tithi boundaries to about 7 s.
- **Festivals:** 116 of 116 in-sample dates and 4 of 5 out-of-sample dates match.
  - Known miss: Thrissur Pooram 2027 (announced 17 April; the rule gives 14 May). `FestivalCalendar.candidates()` shows both days.
- Supported range: 1900–2100. Outside it the SDK throws an error; it never returns a guess.

## Performance

JVM, measured by `PerformanceTest`:

| Operation | Cost |
|---|---|
| First conversion on a new calendar (includes JIT warm-up) | ~85 ms |
| `fromGregorian` with a warm cache | ~0.3 µs |
| All month boundaries 1900–2100 | ~0.3 s |
| `Panchangam.day` | ~0.25 ms |
| `festivalsIn(year)` (25 festivals) | ~25 ms |
| Memory for the full 1900–2100 boundary cache | ~350 KB |

The sample app's release APK, minified with R8 and including Compose, is 1.4 MB.

## Known limitations

- Almanac evidence: 21 cited month starts against the 1.0 target of 60 or more.
- ΔT uses the Espenak–Meeus polynomials: about 5 s high today, diverging by up to 2 minutes by 2100. This only matters for borderline months.
- Not computed: Ashtami Rohini, Dhanu Thiruvathira, Thaipooyam, and Islamic festivals (moon sighting). Add them as dated observances.
- The Android components have no automated UI tests yet.
